# Kioskin

Windows-приложение с полупрозрачным оверлей-окном и локальным HTTP API для управления содержимым и состоянием окна.

Окно по умолчанию занимает нижнюю половину выбранного монитора. Текст отображается в статическом поле внутри окна. Прозрачность управляется через API.

## Требования

- Windows
- Go 1.25+

## Запуск

```bash
go run .
```

или (рекомендуется для распространения — без окна консоли):

```bash
go build -ldflags="-H=windowsgui" -o kioskin.exe .
.\kioskin.exe
```

Флаг `-H=windowsgui` собирает приложение в GUI-подсистеме Windows: окно
консоли не открывается. Приложение ничего не пишет в консоль (логирование
отключено).

После запуска HTTP-сервер слушает порт **8282**:

```
http://localhost:8282
```

Интерактивная документация API (Swagger UI): **http://localhost:8282/docs**

## Конфигурация

Файл `config.json` в рабочей директории:

```json
{
  "monitor_index": 0,
  "logo_path": "logo.png"
}
```

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `monitor_index` | `int` | `0` | Индекс монитора для размещения окна (см. `GET /monitors`) |
| `logo_path` | `string` | — | Путь к PNG/JPEG логотипу. Если не задан или файл не найден — используется встроенный `assets/logo.png` |

Если файл отсутствует, повреждён или индекс вне диапазона — используется монитор `0` или основной экран.

## API

Подробное описание эндпоинтов: [docs/API.md](docs/API.md).

Машиночитаемая спецификация: [openapi.yaml](openapi.yaml).

| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/update` | Показать список покупок (`{"goods": [...]}`), сделать окно непрозрачным |
| `GET` | `/clear` | Очистить список/окно, вернуть полупрозрачный режим |
| `GET` | `/socials` | Развернуть окно на весь экран и показать `assets/socials.png` |
| `GET` | `/health` | Проверка доступности сервиса |
| `GET` | `/monitors` | Список подключённых мониторов |
| `GET` | `/shutdown` | Graceful shutdown приложения |
| `GET` | `/docs` | Swagger UI (редирект на интерактивную документацию) |
| `GET` | `/openapi.yaml` | OpenAPI-спецификация (встроена в бинарник) |

### Быстрый пример

```bash
# Проверка
curl http://localhost:8282/health

# Показать список покупок (весь чек одним запросом)
curl -X POST http://localhost:8282/update \
  -H "Content-Type: application/json" \
  -d '{"goods":[{"name":"Молоко 3.2% 950мл","quantity":2,"price":89.90,"sum":179.80}]}'

# Очистить список / окно (новый чек)
curl http://localhost:8282/clear

# Показать socials-картинку на весь экран
curl http://localhost:8282/socials

# Список мониторов
curl http://localhost:8282/monitors
```

## Поведение окна

- **Начальное состояние:** текст `.`, прозрачность ~20% (`alpha = 50`).
- **После `/update`:** логотип сверху по центру, под ним — список покупок в виде таблицы (Наименование, Кол-во, Цена, Сумма) с зелёной шапкой (цвет креста логотипа), чередующимся фоном строк, переносом длинных наименований и строкой ИТОГО; прозрачность 100% (`alpha = 255`). Присылается весь список одним запросом (`{"goods": [...]}`) и заменяет предыдущий.
- **После `/clear`:** список очищается, логотип скрывается, текст сбрасывается в `.`, прозрачность возвращается к ~20%, окно возвращается к половинному размеру.
- **После `/socials`:** окно разворачивается на весь выбранный монитор, прозрачность 100% (`alpha = 255`), текст и логотип скрываются, по центру показывается `assets/socials.png` (вписана с сохранением пропорций). `/update` и `/clear` возвращают окно к половинному размеру.
- Окно без рамки (`WS_POPUP`), заголовок — `Kioskin`.
- При закрытии окна пользователем приложение пересоздаёт его (цикл в `main`), пока не вызван `/shutdown`.

## Иконка и манифест

Ресурс `rsrc.syso` встраивает в бинарник **манифест** и **иконку**:

- Манифест (`kioskin.exe.manifest`) — DPI-awareness и тема Common Controls v6;
  вшит в exe, отдельный файл рядом не нужен.
- Иконка — Windows использует её как иконку `.exe`; она же назначается окну
  (`ClassIconId`), а стиль `WS_EX_APPWINDOW` показывает кнопку окна на панели
  задач — поэтому во время работы приложение видно на панели задач с иконкой.

Исходник иконки — `assets/icon.png`, из него генерируется `assets/icon.ico`
(вписывается по центру квадрата с сохранением пропорций; размеры не больше
исходного, для 32×32 — 16/24/32).

> **Важно:** `rsrc` нумерует ресурсы по порядку — манифест получает ID `1`,
> группа иконок `2`. Поэтому в коде `appIconResID = 2`. Если убрать `-manifest`
> из команды ниже, иконка станет ID `1`, и константу нужно вернуть на `1`.

Чтобы обновить иконку после смены `assets/icon.png`:

```bash
# 1. Пересобрать assets/icon.ico из PNG
go run ./tools/genico assets/icon.png assets/icon.ico

# 2. Перегенерировать ресурс rsrc.syso (манифест + иконка)
go run github.com/akavel/rsrc@latest -manifest kioskin.exe.manifest -ico assets/icon.ico -o rsrc.syso

# 3. Пересобрать приложение (go build подхватит rsrc.syso автоматически)
go build -ldflags="-H=windowsgui" -o kioskin.exe .
```

## Распространение

Для запуска на другом компьютере достаточно **одного файла `kioskin.exe`**:

- логотип, картинка socials, спецификация OpenAPI, иконка и манифест — всё
  вшито в бинарник;
- Go-бинарник статический, сторонних DLL и рантайма не требует (только
  системные библиотеки Windows);
- `config.json` **необязателен** — без него используется монитор `0` и
  встроенный логотип. Нужен, только чтобы задать `monitor_index` или внешний
  `logo_path` (в последнем случае рядом должен лежать и указанный файл).

## Автообновление и релизы

Работающие киоски сами скачивают и устанавливают новые версии из GitHub Releases.

**Как выпустить версию:**

```bash
git tag v1.0.0
git push origin v1.0.0
```

Пуш тега `vX.Y.Z` запускает GitHub Actions ([.github/workflows/release.yml](.github/workflows/release.yml)),
который собирает `kioskin.exe` (с зашитой версией через `-ldflags -X main.version`),
считает его `SHA-256` и публикует оба файла в Release с этим тегом.

**Как обновляются киоски:**

- При старте и затем раз в час приложение опрашивает
  `GET /repos/Natrix31/kioskin/releases/latest` (GitHub API).
- Если тег последнего релиза отличается от текущей версии — скачивает
  `kioskin.exe`, проверяет его `SHA-256` по ассету `kioskin.exe.sha256`,
  и только при совпадении заменяет себя и перезапускается.
- Замена: запущенный exe переименовывается в `kioskin.exe.old`, новый ставится
  на его место, стартует новый процесс, старый завершается; `.old` удаляется
  при следующем запуске.

**Текущая версия** видна в `GET /health` (`{"status":"ok","version":"v1.0.0"}`).

**Локальные сборки** (`go build` без `-X main.version`) имеют версию `dev` —
для них автообновление **отключено**, чтобы дев-машины не подменяли бинарник.

> **Безопасность:** проверка `SHA-256` защищает от битой/оборванной загрузки, но
> не от компрометации самого репозитория (злоумышленник с доступом на запись
> подменит и бинарник, и сумму). Канал — HTTPS к GitHub. Для строгой гарантии
> подлинности нужна подпись кода; при необходимости добавим.
>
> GitHub API без токена ограничен 60 запросами/час на IP. При большом парке
> киосков за одним внешним IP (1 проверка/час на киоск) лимит достижим — тогда
> стоит добавить токен или увеличить интервал.
